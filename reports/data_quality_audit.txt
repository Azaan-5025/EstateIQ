7. SYNTHESIS OF DISCOVERED ISSUES & RECOMMENDED REMEDIATION ACTIONS
================================================================================
--------------------------------------------------------------------------------
ISSUE #1: Floor Structure Anomaly
--------------------------------------------------------------------------------
Observed Problem   : 46.52% of rows (116,304 records) have Floor_No > Total_Floors across all property types. Furthermore, Villas and Independent Houses exhibit Floor_No and Total_Floors up to 30.
Root Cause         : Simulated generation artifact where Floor_No and Total_Floors were drawn independently from Uniform(0, 30).
Recommended Action : Do not discard nearly half the dataset. Recommended approach for preprocessing/features: (a) For Villas and Independent Houses, create an engineered building height proxy or override structural floor level; (b) For Apartments, create a logical relative floor position ratio `Relative_Floor_Position = min(Floor_No, Total_Floors) / max(Total_Floors, 1)` or clip `Floor_No = min(Floor_No, Total_Floors)` while creating a binary indicator flag `Floor_Mismatch_Flag` so models can leverage the signal without distorted mathematical ratios.

--------------------------------------------------------------------------------
ISSUE #2: Price_per_SqFt Rounding & Zero Values
--------------------------------------------------------------------------------
Observed Problem   : Price_per_SqFt is stored in Lakhs/SqFt rounded to 2 decimal places. For 467 records, calculated unit price is < 0.005 Lakhs/SqFt (e.g. Rs 2,222 to Rs 4,999/SqFt), causing Price_per_SqFt to round to 0.00. Additionally, 2-decimal rounding in Lakhs causes loss of precision.
Root Cause         : Precision loss from representing unit price in Lakhs with only two decimal places.
Recommended Action : In Phase 2/3 Feature Engineering, compute high-precision `Price_per_SqFt_INR = (Price_in_Lakhs * 100000) / Size_in_SqFt`. This guarantees exact rupee pricing, completely eliminates zero-value unit prices, and accurately captures real estate dynamics.

--------------------------------------------------------------------------------
ISSUE #3: Property Age & Year_Built Redundancy
--------------------------------------------------------------------------------
Observed Problem   : Age_of_Property is strictly equal to (2025 - Year_Built) across all 250,000 records (0 mismatches).
Root Cause         : Deterministic linear identity.
Recommended Action : During model training and feature selection, retain only one of the two features (e.g., `Age_of_Property`) to prevent perfect multicollinearity in linear models and redundant splits in tree-based algorithms.

--------------------------------------------------------------------------------
ISSUE #4: Identifier (ID)
--------------------------------------------------------------------------------
Observed Problem   : ID is an unbroken sequential integer from 1 to 250,000 with 0 duplicates and 0 missing values.
Root Cause         : Standard database primary key.
Recommended Action : Drop `ID` from feature matrices prior to model training to prevent arbitrary index leakage.

--------------------------------------------------------------------------------
ISSUE #5: Amenities Multi-Label Representation
--------------------------------------------------------------------------------
Observed Problem   : Amenities column contains 325 unique comma-separated permutations composed of exactly 5 atomic items: ['Clubhouse', 'Garden', 'Gym', 'Playground', 'Pool'].
Root Cause         : Un-normalized multi-select string encoding.
Recommended Action : In Feature Engineering, decompose Amenities into: (a) 5 binary flag columns (`Has_Gym`, `Has_Pool`, `Has_Garden`, `Has_Playground`, `Has_Clubhouse`), and (b) An aggregate `Total_Amenities_Count` (0 to 5) reflecting luxury/lifestyle score.

--------------------------------------------------------------------------------
ISSUE #6: Categorical Encodings & Locality Cardinality
--------------------------------------------------------------------------------
Observed Problem   : Controlled categoricals (Property_Type, Furnished_Status, Facing, Owner_Type, Availability_Status, Public_Transport_Accessibility, Parking_Space, Security) are exceptionally clean with 0 whitespace issues. However, `Locality` has 500 levels, `City` has 42 levels, and `State` has 20 levels.
Root Cause         : High-cardinality geographical hierarchy.
Recommended Action : Apply binary/one-hot encoding to low-cardinality nominals (8 features). For high-cardinality geography (Locality and City), use out-of-fold target encoding, frequency encoding, or median price-per-sqft group aggregations calculated strictly on training folds to prevent data leakage.
